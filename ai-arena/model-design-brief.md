# 模型角色设计委托模板

版本：1.0。用途：将同一份规则约束提交给 DeepSeek、Claude、Gemini、GPT 等对应模型，得到可审查的原创角色方案。当前文件是委托输入，不代表已经调用这些模型。正式接入时先以当前引擎导出的规则和可用招式类型替换下方建议基线。

## 给模型的统一任务

你正在为原创本地双人格斗游戏设计一个以你所属模型家族为灵感的角色。请独立选择形象、技能名称、玩法与弱点。你可以参考自己的能力特征，但不能声称评测分数直接等于格斗强度。所有角色共享底层移动、防御、碰撞、能量和胜负规则。禁止让你的角色修改全局规则、拥有必胜判定或无法反制的连续控制。

先提出两个不同风格方案，逐一解释对手如何应对，再选择一个实现成本较低、特点鲜明的方案。输出角色介绍、帧数据、数值、招式联动、弱点和测试案例。你的身份与 API 元数据由调用方记录，不需要自行猜测具体模型版本。

## 建议约束 需要由当前引擎版本确认后锁定

- 所有数值按 60 Hz 模拟帧表达；必须列前摇、有效帧、后摇，不能只给总冷却。
- 每角色使用同一生命基准；不得用不同生命值补偿尚未验证的技能强弱。
- 普攻伤害建议为最大生命的 3%–8%；重击 7%–15%；技能 8%–20%；超必杀 18%–30%。这些是候选设计范围，不是全部取上限的配额。
- 单次脱离中立的连段总伤害目标不超过 40% 最大生命；高伤害组合必须消耗资源或承担明显风险。
- 至少提供一种中立距离弱点和一种被防御后的可惩罚行为。
- 同一技能不能同时拥有最快起手、最长射程、无敌、无资源消耗和安全后摇。
- 机制范围优先使用位移、单次飞行道具、短时反击、空中变向；召唤、多目标、时间停止与复制对手整套技能先留作后续提案。
- 防御损耗、无敌窗口、资源回收和连段上限由引擎统一裁定。必须在范围内设计，不能绕过它们。
- 所有造型、招式表现与命名原创。列清角色的轮廓、主辅色、行动风格，不提供任何现成游戏拆包素材。

## 输出格式

先给一段可供玩家理解的玩法说明，再给下列 JSON。JSON 只含数据，不得包含 JavaScript、脚本、文件路径或可执行表达式。无依据的评测分数留空。

```json
{
  "schemaVersion": "1.0",
  "family": "填写对应模型家族",
  "displayName": "原创角色称号",
  "archetype": "近战 / 控场 / 防反 / 空中之一或清楚的新定义",
  "visual": {
    "silhouette": "剪影与服装结构",
    "colors": ["#000000", "#FFFFFF"],
    "animationIntent": "待机与攻击的动作意图"
  },
  "designReason": "为什么这些技能形成可玩的决策",
  "strengths": [],
  "weaknesses": [],
  "moves": [
    {
      "id": "special",
      "name": "原创名称",
      "mechanism": "projectile",
      "startupFrames": 0,
      "activeFrames": 0,
      "recoveryFrames": 0,
      "damageFraction": 0,
      "energyCost": 0,
      "rangeUnits": 0,
      "hitbox": {"offsetX": 0, "offsetY": 0, "width": 0, "height": 0},
      "hitStunFrames": 0,
      "blockStunFrames": 0,
      "allowedCancelInto": [],
      "counterplay": "对手如何判断并反制"
    }
  ],
  "combos": [],
  "testCases": [],
  "benchmarkReferences": []
}
```

示例中的 0 仅为字段占位，不能作为有效招式直接导入。最终由设计审查器拒绝缺失、越界和引擎暂不支持的字段。

## 调用方必须另存的来源记录

```json
{
  "designStatus": "placeholder | model_generated | reviewed | tournament_locked",
  "provider": "实际调用服务商",
  "modelId": "API 返回或请求中固定的完整模型 ID",
  "generatedAt": "ISO 8601 时间",
  "promptVersion": "1.0",
  "rulesetVersion": "当前引擎固定版本",
  "requestSettings": {},
  "requestHash": "原始请求的哈希",
  "responseHash": "原始回复的哈希",
  "reviewer": "实际审查者",
  "reviewNotes": [],
  "balancePatch": "候选补丁号"
}
```

密钥不进入浏览器，也不写入来源记录。保存原始回复是为了审查来源，不能只保留整理后的角色卡。当前代拟角色保持 `placeholder`，只有实际调用成功后才能标为 `model_generated`；比赛批准是后续独立状态。

## 竞速设计的独立追加任务

请为同一角色设计一个竞速技能，说明它如何改变路线决策、何时使用最好、失败代价是什么。所有角色共享基础移动速度、跳跃高度、碰撞体和复位规则。候选技能只影响短时操作选择，不允许永久速度优势、强制传送到终点、回收检查点奖励或让对手无法继续前进。输出持续帧数、冷却帧数、位移上限、环境碰撞行为和至少三个测试案例。

首轮竞速样本使用统一能力，专属技能进入后续实验分支；避免在基础赛道尚不稳定时同时引入多个平衡变量。
